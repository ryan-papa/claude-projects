# Harness: 글쓰기 원칙

> 참고 가이드(감점·차단 없음). 하네스가 생산하는 **모든 한국어 산출물**에 적용 — 문서(docs·PRD·태스크), 리뷰 리포트, 커밋·PR 본문, README, 터미널 응답.

읽는 사람의 시간을 줄이는 것이 목표다. 짧게 쓰는 것이 아니라 **한 번에 이해되게** 쓴다.

## 구조 (문서·문단)

| # | 원칙 | 판정 기준 | 반례 → 대체 |
|:-:|------|----------|------------|
| 1 | 결론 먼저 | 첫 문장·첫 행만 읽고 결정할 수 있는가 | "여러 방안을 검토한 결과 …" → "A로 간다. 이유는 B" |
| 2 | 한 문단 한 주제 | 문단에서 주제문 1개를 뽑을 수 있는가 | 한 문단에 원인·대안·일정이 섞임 → 문단 분리 |
| 3 | 3개 이상은 표로 | 같은 축으로 비교되는 항목이 3개 이상이면 산문 금지 | 항목을 쉼표로 나열한 긴 문장 → 표 |

## 문장

| # | 원칙 | 판정 기준 | 반례 → 대체 |
|:-:|------|----------|------------|
| 4 | 한 문장 한 뜻 | 문장에 서술어가 2개 이상인가 | "A를 고쳤고 B도 검토했는데 C는 보류다" → 3문장 |
| 5 | 짧게 | 50자 초과 문장이 연속 2개 이상인가 | 초과 시 접속어에서 자름 |
| 6 | 주어·서술어 근접 | 주어와 서술어 사이 수식이 20자를 넘는가 | 수식절을 앞이나 뒤 문장으로 뺌 |
| 7 | 능동·주체 명시 | 누가 하는지 문장에 있는가. 이중피동 0건인가 | "적용되어집니다 / 판단되어진다" → "적용한다 / 판단한다" |
| 8 | 번역투 제거 | 아래 표현이 0건인가 | "~에 대하여 / ~에 있어서 / ~를 통하여 / ~하도록 한다 / ~것으로 보여진다 / ~에 다름 아니다" |

## 단어

| # | 원칙 | 판정 기준 | 반례 → 대체 |
|:-:|------|----------|------------|
| 9 | 명사 나열·'의' 연속 금지 | 명사 3개 연결, 관형격 '의' 2회 연속이 있는가 | "성능 개선 작업 진행" → "성능을 개선한다" / "서버의 응답의 지연" → "서버 응답이 늦다" |
| 10 | 어려운 말은 일상어로 | 일상어로 바꿔도 뜻이 유지되는가 (예외: §기술 용어) | "상기 / 익일 / 소요된다 / 제고한다 / 금번" → "위 / 다음 날 / 걸린다 / 높인다 / 이번" |

## 기술 용어 — 항시 보존

**바꾸지 않는다.** 변수·클래스·함수·파일·API·명령어·설정 키 등 코드 식별자, 그리고 개발·기획·리뷰 표준 용어(마이그레이션, 롤백, 인덱스, 커버리지, 스코프, 리드타임 등)는 원어 그대로 쓴다.

- 원칙 10의 대상은 **관용 한자어·번역투·허세 표현**이지 기술 용어가 아니다
- 쉽게 쓸 대상은 용어가 아니라 **그 용어를 설명하는 문장**이다
- 예: "인덱스 미적용으로 인한 풀스캔 발생" → "인덱스가 없어서 풀스캔이 돈다" (인덱스·풀스캔 유지)
- 처음 등장하는 사내·프로젝트 전용 약어만 괄호로 한 번 푼다. 업계 표준어는 풀지 않는다

## 근거

| 대상 | 규칙 |
|------|------|
| 평가·주장 | 측정값과 함께 쓴다. "많이 빨라짐" → "p95 420ms → 180ms" |
| 인용 | 파일·라인·PR 번호 등 확인 가능한 출처를 붙인다 |
| 미확인 값 | `(추정)` 표시 + 판단 근거 1줄. 확인한 척 쓰지 않는다 |

## 퇴고 (제출 전 1회, 3단계)

| 단계 | 작업 | 통과 기준 |
|:----:|------|----------|
| 1 | 삭제 — 지워도 뜻이 남는 문장·수식어를 지운다 | "매우 / 다양한 / 기본적으로 / ~라고 할 수 있다" 0건 |
| 2 | 접기 — 나열을 표로, 반복 설명을 링크로 바꾼다 | 같은 내용이 두 곳에 있지 않음 (SSOT) |
| 3 | 읽기 — 첫 문장만 읽고 결론이 잡히는지 확인 | 안 잡히면 결론 문장을 맨 앞으로 |
