# Harness: 글쓰기 원칙

> 참고 가이드. 하네스에서 생산하는 **모든 한국어 산출물**에 적용 — 문서(docs·PRD·태스크), 리뷰 리포트, 커밋·PR 본문, README, 터미널 응답.

## 원칙 10

| # | 원칙 | 지침 | 반례 → 대체 |
|:-:|------|------|------------|
| 1 | 결론 먼저 | 판단·결과를 첫 문장에. 배경·과정은 뒤 | "여러 방안을 검토한 결과 …입니다" → "A로 간다. 이유는 …" |
| 2 | 한 문장 한 뜻 | 한 문장에 정보 하나. 두 뜻이면 자름 | 접속조사로 3절 이상 이어붙인 문장 |
| 3 | 짧게 | 문장은 50자 안쪽을 기본으로 | 수식어가 주어에서 서술어까지 이어지는 문장 |
| 4 | 능동·주체 명시 | 누가 무엇을 하는지 드러냄. 이중피동 금지 | "적용되어집니다" → "적용한다" |
| 5 | 번역투 제거 | 한국어 어순으로 | "~에 대하여 / ~에 있어서 / ~를 통하여 / ~하도록 한다 / ~것으로 보여진다" |
| 6 | 명사 나열 금지 | 명사 3개 이상 붙이지 않음. 관형격 '의' 연속 금지 | "성능 개선 작업 진행" → "성능을 개선한다" |
| 7 | 군더더기 삭제 | 지워도 뜻이 남으면 지움. 빈 수식어·중복 표현 배제 | "매우 다양한 / 효율적으로 / 기본적으로" |
| 8 | 수치로 말함 | 평가·주장은 측정값·근거와 함께 | "많이 빨라짐" → "p95 420ms → 180ms" |
| 9 | 어려운 말 대체 | 일상어로 바꿔도 뜻이 유지되면 바꿈 (예외: 아래 §기술 용어) | "상기 / 익일 / 소요된다 / 제고한다" → "위 / 다음 날 / 걸린다 / 높인다" |
| 10 | 한 번 줄임 | 초안 완성 후 문장 수·글자 수를 줄이는 퇴고 1회 | 초안을 그대로 제출 |

## 기술 용어 — 항시 보존

**바꾸지 않는다.** 변수·클래스·함수·파일·API·명령어·설정 키 등 코드 식별자, 그리고 개발·기획·리뷰에서 쓰는 표준 용어(마이그레이션, 롤백, 인덱스, 커버리지, 스코프, 리드타임 등)는 원어 그대로 쓴다.

- 원칙 9의 대상은 **관용적 한자어·번역투·허세 표현**이지 기술 용어가 아니다
- 쉽게 쓸 대상은 용어 자체가 아니라 **그 용어를 설명하는 문장**이다
- 예: "인덱스 미적용으로 인한 풀스캔 발생" → "인덱스가 없어서 풀스캔이 돈다" (인덱스·풀스캔은 유지)
