# 간소 PRD: 인프라 리뷰 신설 + 리뷰 단계 병렬화

**유형:** 하네스 메타 변경

## 변경 이유

**문제 1 — 코드↔인프라 접점 중 명문화 공백.** 현행 [9] 코드 리뷰 항목 6(성능)은 N+1·전체 테이블 스캔·무한 증가 컬렉션까지만 커버한다([`../../harness-code-review.md`](../../harness-code-review.md) L129). 아래 4종은 7항목 어디에도 없어 리뷰어 재량에 맡겨진다.

| 공백 | 대표 실패 모드 (일반 패턴, 본 레포 관측 사례 미보유) |
|------|------------------------------------------|
| SQL 방언 정합(MySQL↔StarRocks), 숫자 타입 정밀도 | 실행 실패, 금액 오차 누적 |
| 캐시·메시지 객체 직렬화 호환 | 롤아웃 중 역직렬화 예외 |
| 코루틴 블로킹 중첩 | 스레드풀 고갈 |
| 배포 전략 하 구·신 동시 존재, pub/sub 계약 변경 | 부분 트래픽 장애 |

**근거 상태 명시:** 위 실패 모드는 일반 패턴이며 `docs/research/` 발췌 근거를 첨부하지 않았다(1a·1b 신설 때와 달리 선행 관측이 없음). 따라서 본 변경은 **효과 검증 트리거(§검증)를 전제로 한 잠정 도입**이며, 관측 미달 시 축소·폐기 조건을 사전 명시한다.

**문제 2 — 인프라 상태를 하네스가 모른다.** 인덱스 존재·파티션·토픽 설정은 코드만으로 확인 불가하다. 점수제 차단 게이트로 만들면 오탐이 절차를 막는다. 따라서 신설 축은 **자문이 1차 목적**, 차단은 diff 만으로 확정 가능한 결함으로 한정한다.

**문제 3 — 리뷰 단계 직렬.** [4]→[5] 순차. 두 관점은 서로의 결과를 입력으로 쓰지 않아 병렬 가능. wall-clock 베이스라인 미보유 → §검증에서 기록 주체를 지정해 관측한다.

### 인프라 리뷰 5영역

| # | 영역 | 검사 내용 | 등급 |
|:-:|------|----------|------|
| 1 | SQL 품질 | 방언 정합(대상 엔진 미지원 문법·함수·예약어) / 실행계획 추정(인덱스 활용 **가능성**·풀스캔·깊은 OFFSET·`SELECT *` — 인덱스 존재 여부는 미확인 전제, 확정 표현 금지) / 타입·정밀도(금액·율에 `double` 대신 `decimal(p,s)`, 자릿수·스케일 부족, 암묵 형변환 인덱스 무효화, 콜레이션 불일치) / 쓰기 패턴(대량 insert 배치 **500~2000건**, 배치 간 슬립은 **복제 지연·부하 지표 기반 조절 권고**, 관측치 없을 때 보수적 기본값 **1초**) / 트랜잭션 범위, 무제한 UPDATE·DELETE, DDL 락·다운타임 | 전부 WARN |

| 3 | 비동기·스레드 점유 | 중첩·루프 내 `runBlocking` → **BLOCK** / 단일 `runBlocking`·`GlobalScope`·Default 디스패처 blocking IO·타임아웃 없는 외부 API 호출 → WARN + 대안 제시 | 혼합 |
| 4 | 직렬화 호환 | 파괴적 스키마 변경 → **BLOCK** / nullable·기본값 있는 필드 추가 → WARN | 혼합 |
| 5 | 배포·pub/sub | 매니페스트·CI로 전략 판별(미판별 시 "롤링 가정" 명시). 카나리·롤링은 구·신 동시 존재 전제 → 스키마·캐시 포맷·메시지 계약·구독(토픽·컨슈머그룹·파티션) 변경 위험 + **선행 인프라 작업 목록** 제시 | 전부 WARN |

### BLOCK·ASK 부여 조건 (정적 확정 가능해야 부여)

| 등급 | 부여 조건 (전부 충족) | 제외 — WARN 처리 |
|------|---------------------|-----------------|
| **B1** 중첩·루프 `runBlocking` | 동일 함수 본문 내 직접 중첩, 또는 반복문·스트림 본문 내 `runBlocking` 호출이 diff 에 보임 | 호출 경로상 **간접** 중첩(콜그래프 미확정) / 테스트 코드·`main()`·일회성 CLI·배치 스크립트의 관용 사용 |
| **B2** Redis 전체 키 순회 | `KEYS`·`keys('*')` 호출, 또는 커서 종료 조건·배치 상한이 **없는** SCAN 루프 | 종료 조건 + `COUNT` 상한이 있는 정상 커서 페이지네이션 / 테스트 픽스처·로컬 운영 도구 |
| **B3** 파괴적 직렬화 변경 | (i) 대상 타입이 캐시 저장 또는 메시지 페이로드로 쓰임을 **diff 또는 diff 가 참조하는 직접 호출부**에서 확인(전역 탐색 불요) + (ii) 필드 삭제·타입 변경·이름 변경·enum 값 제거·FQCN 이동 중 1건 | 신규 도입 타입(구버전 소비자 부재) / 마이그레이션·버전 필드가 동반된 변경 / **(i) 확정 불가 시 WARN 강등** |
| **ASK** Redis 값 2MB 초과 | (i) 크기 상한이 코드에 없음 + (ii) 건수·요소당 크기 근거를 코드·스키마에서 **인용 가능** | 근거 인용 불가 시 WARN 강등 |

**인용 의무·해제 경로 (BLOCK·ASK 공통, 대칭 적용):**

1. 부여 시 파일·줄 인용 **의무**. 인용 불가 → 한 등급 강등(BLOCK→WARN, ASK→WARN)
2. Dev Agent 가 정적 근거로 반박 시 → BLOCK 은 ASK 로, ASK 는 사용자 결정으로 이관. **사이클당 1회, 재반박 금지**
3. **최종 심사 주체는 사용자.** 반박은 판정 번복이 아니라 **결정 이관**이므로 메인 셀프 채점 금지 조항과 무충돌 — SSOT 에 이 취지를 1줄 명문화
4. ASK 사용자 결정(강행/수정/분할)과 근거는 PR 본문 노트에 1줄 기록. **강행 시 같은 사이클 내 재제기 금지**

### 지적 후처리 (자동 수정 범위)

| 구분 | 처리 |
|------|------|
| BLOCK + **코드 등가 치환** WARN (`decimal` 전환, `SELECT *` 컬럼 명시, 깊은 OFFSET → 커서 페이징, 암묵 형변환 제거, 타임아웃 부여) | 1차 리뷰 종료 후 Dev Agent 자동 수정 |
| **런타임 동작·소요 시간을 바꾸는** WARN (배치 크기, **슬립 삽입**, TTL, 캐시 분할) | **자동 수정 금지** — 권고값·근거만 제시. 근거 없는 지연 자동 주입으로 성능을 회귀시키지 않기 위함 |
| 인프라 의존 WARN (인덱스·파티셔닝·토픽 설정·리소스 증설) | 자동 수정 금지. PR 본문 "인프라 선행 작업"으로 분리 |
| ASK | 진행 중단 + 사용자 결정 |

### 병렬화 · 재시도 · 카운트

- **[4] ∥ [5]**, **[9-코드] ∥ [9-인프라]**: 동일 메시지에서 두 서브에이전트 동시 발사, 컨텍스트 미공유 독립 판정
- **Codex-Lead 대칭**: `spawn_agent` 동시 발사 불가 환경이면 **순차 fallback 허용** — 판정 규칙·통과 조건 동일, 실행 순서만 다름. 병렬 여부를 통과 조건에 넣지 않는다
- **조건부 재검증**: 미달 축만 재실행하되, 수정이 상대 관점 영역을 건드리면 통과한 축도 재검증
  - [4]↔[5]: 기능 요구사항 증감·스코프 경계 변경 → [4] / 아키텍처·데이터 모델·성능·보안·운영 서술 변경 → [5] / **PRD 전면 개작 시 무조건 양축 재실행**
  - [9]: SQL·Redis·직렬화 대상 타입·배포 매니페스트 변경 → 인프라 / 비즈니스 로직·공개 API·테스트 변경 → 코드
  - **"1회 한정" = 같은 사이클 내 재검증→재검증 연쇄 금지.** 재검증 결과가 미달이면 그 축은 **다음 사이클의 미달 축**으로 전환되어 정상 재시도 경로를 탄다(교착 없음). 다음 사이클에서는 재검증 규칙이 다시 적용되며, 종료는 카운트 상한이 보장
- **카운트** (기존 한도 불변, 증액 없음):

| 단계 | 카운터 | 소비 규칙 |
|------|--------|----------|
| [4]·[5] | **축별 독립** 각 3회 | 해당 축 재실행 시 그 축만 1회 소비. 조건부 재검증은 **소비 없음** |
| [9] | 코드+인프라 **공통** 5회 | **사이클 단위** — 한 사이클에서 어느 축이든 1개 이상 재실행하면 1회 소비. 조건부 재검증은 소비 없음 |
| 공통 | — | ASK 발생 자체는 **미소비**. ASK 후 코드 수정하여 재실행하면 그 사이클이 1회 소비. 기술 실패 재호출은 별도 카운트(기존 SSOT) |

- **부분 기술 실패**: 한 축만 실패 시 해당 축만 최대 2회 재호출(총 3회). 정상 축 결과 보존. 지속 시 중단 + 사용자 보고. **실패 축을 생략한 통과 판정 금지**
- **실효 재시도 축소 인지**: [9] 5회를 2축이 공유하면 교대 실패 시 축당 여력이 줄어든다. 한도는 유지하되 §검증의 소진 관측으로 재평가한다

### PR 본문 "인프라 리뷰 노트"

- 구성: (1) 판정 요약(BLOCK/ASK/WARN 건수) (2) 자문 지적 (3) **인프라 선행 작업** 체크리스트
- **식별 정보 일반화 의무**: 호스트·계정·내부 IP·인증서 경로 기재 금지. 인덱스명·토픽·컨슈머그룹·테이블명은 역할 기술로 일반화(`주문 조회용 복합 인덱스`)
- `rp-ship` 배포 전 체크에 **인프라 축 이수 확인** 추가. **정당한 skip(콘텐츠·메타 변경·N/A 반환)은 이수로 간주** — 기존 `rp-ship.md` QA·코드리뷰 이수 확인의 메타 단축 경로 예외와 동일 처리. 선행 작업 항목은 미이행이어도 차단하지 않음(인프라 상태 확인 불가 원칙)
